### 3. contracts/order.placed.json

`order.placed` payload의 JSON Schema:
`{ order_id (uuid), items: [{sku, qty}], card_number, amount }`.
정본. 덩어리 20 이후 CI에서 서비스 Pydantic 모델 출력 검증에 사용.

### 4. pipeline-kafka: envelope 모델 + 직렬화

`Envelope` Pydantic 모델: `event_id`, `event_type`, `occurred_at`, `correlation_id`, `producer`, `schema_version`, `payload`.
헬퍼: `Envelope.new(event_type, correlation_id, producer, payload)` (event_id=uuid4, occurred_at=now).
`to_kafka(envelope) -> (key: str, value: bytes, headers: list[tuple])` — key=correlation_id,
headers에 `message-id`(=event_id), `correlation-id`, `traceparent`(덩어리 9에서 채움).
`from_kafka(msg) -> Envelope`.

### 5. pipeline-kafka: producer 래퍼

confluent `Producer` 얇은 래퍼. `KafkaPublisher.publish(topic, envelope)` → `to_kafka` → `produce` → 헤더 세팅.
flush 정책: 폴러가 배치 끝에 `flush()`. produce 시 produce 스팬 시작 + traceparent 주입(덩어리 9).

### 6. pipeline-kafka: outbox

테이블 모델(SQLAlchemy declarative): `outbox(id BIGSERIAL PK, topic, key, headers JSONB, payload JSONB, created_at, published_at NULL, next_attempt_at)`.
- `enqueue(session, topic, envelope)` — 호출자 tx 안에서 행 INSERT.
- `OutboxPoller(session_factory, publisher, batch=100, interval=0.5s)` — asyncio 태스크.
  `SELECT ... WHERE published_at IS NULL AND next_attempt_at <= now() ORDER BY id LIMIT :batch FOR UPDATE SKIP LOCKED`
  → `publisher.publish` → `published_at = now()`. 단일 폴러/서비스, id 순 → 순서 유지.
  S0: 발행 실패 시 그냥 다음 tick. (백오프는 S2)

### 7. pipeline-kafka: inbox

테이블 모델: `inbox(message_id UUID, consumer_group TEXT, handled_at TIMESTAMPTZ, PK(message_id, consumer_group))`.
- `already_handled(session, message_id, group) -> bool`
- `mark_handled(session, message_id, group)` — 호출자 tx 안에서 INSERT (PK 충돌 = 중복).
정리 배치: `handled_at < now() - 7d` 삭제 (S0에선 스텁만, cron은 나중).

### 8. pipeline-kafka: 컨슈머 런타임

`run_consumer(topics, group_id, handler, session_factory, *, stop_event)`:
```
Consumer({enable.auto.commit=false, auto.offset.reset=earliest, ...})
subscribe(topics, on_revoke=commit 콜백)
while not stop_event:
    msg = poll(1.0)
    envelope = from_kafka(msg)
    traceparent 추출 → consume 스팬 시작
    async with session_factory() as session, session.begin():
        if already_handled(session, envelope.event_id, group_id): continue (오프셋은 커밋)
        await handler(session, envelope)          # 도메인 로직 + outbox.enqueue
        mark_handled(session, envelope.event_id, group_id)
    consumer.commit(msg)                          # tx 커밋 후
on_revoke: 현재까지 오프셋 커밋
```
handler 시그니처: `async def handler(session, envelope) -> None`.

### 9. pipeline-kafka: OTel 배선

`setup_telemetry(service_name)` — TracerProvider + OTLP gRPC exporter(→ collector) + resource(service.name).
`inject_traceparent(headers)` / `extract_context(headers)` — W3C TraceContext propagator를 Kafka 헤더에 매핑.
producer(덩어리 5) produce 시 inject, consumer(덩어리 8) poll 시 extract → 스팬 부모로.

### 10. order-service: domain/

`OrderStatus` enum — 전체 정의 (PLACED, RESERVED, PAID, COMPLETED, CANCELLING, CANCELLED). S0은 PLACED만 사용.
`OrderItem` VO (sku, qty). `Order` 엔티티 (id, items, card_number, amount, status).
`Order.place(items, card_number) -> Order` 팩토리 (id=uuid4, status=PLACED, amount 계산).
프레임워크 import 0.

### 11. order-service: application/

포트 (Protocol): `OrderRepository.add(order)`, `OrderRepository.get(id)`.
`UnitOfWork` — `orders: OrderRepository`, `enqueue(topic, envelope)`, `__aenter__/__aexit__` (begin/commit/rollback).
유스케이스 `PlaceOrder(uow_factory)`:
```
async def execute(cmd: PlaceOrderCommand) -> OrderId:
    order = Order.place(cmd.items, cmd.card_number)
    async with uow_factory() as uow:
        await uow.orders.add(order)
        uow.enqueue("order.events", Envelope.new("order.placed", order.id, "order-service", payload))
    return order.id
```

### 12. order-service: adapters/outbound/

SQLAlchemy `orders` 테이블 + `SqlOrderRepository` (포트 구현).
`SqlAlchemyUnitOfWork` — async session 래핑, `orders` 프로퍼티, `enqueue`는 `pipeline_kafka.outbox.enqueue(self.session, ...)` 위임.
`__aenter__` = session 열기, `__aexit__` = commit/rollback + close.
