## 덩어리 상세

### 1. 레포 뼈대 + uv workspace  ✅ 완료

실제 진행: `uv init --bare`(루트) → `uv init --lib libs/pipeline-kafka` →
`uv init --package services/order-service` → 중첩 `.git` 제거 → `uv add --package <멤버> <deps>`.
빌드 백엔드 `uv_build`. `uv add --package X pipeline-kafka`가 `[tool.uv.sources] ... {workspace=true}` 자동 추가.
OTel exporter는 `-proto-http` (gRPC의 grpcio 빌드 회피).

> `order-query-service`도 처음엔 만들었으나 개정으로 삭제.

### 2. docker-compose + 인프라 설정

컨테이너 7개. 스텝: 2-A 백킹 / 2-B 토픽 init / 2-C 관측성(traces).

- **2-A** ✅: `kafka`(`apache/kafka:3.9.1`, KRaft 단일, 로그는 `/tmp` **ephemeral** — Apache
  이미지가 마운트를 chown 안 해서 named volume 불가, 학습 프로젝트엔 재현성 위해 ephemeral이 오히려 나음),
  `kafka-ui`(kafbat, 토픽·메시지·컨슈머 오프셋 육안), `order-postgres`(볼륨 유지, postgres 이미지는 chown함).
  전부 healthcheck. 리스너 2개: `PLAINTEXT_HOST://localhost:9092`(호스트) / `PLAINTEXT://kafka:19092`(컨테이너 간).
- **2-B**: `kafka-init`(원샷, `scripts/create-topics.sh`로 `order.events` 3파티션, `--if-not-exists`).
  S0은 `order.events`만.
- **2-C** ✅: `tempo`(OTLP gRPC 4317 수신, storage local ephemeral), `otel-collector`(OTLP grpc/http
  4317·4318 수신, `otlp/tempo`+`debug` exporter, traces 파이프라인만), `grafana`(익명 Admin,
  `datasources/tempo.yaml` 프로비저닝). **traces만.** Prometheus/Loki/대시보드는 Slice 4.
  코드가 트레이스를 뿜는 건 덩어리 12 — 지금은 받을 그릇만.

설정 파일: `scripts/create-topics.sh`, `observability/otel-collector/config.yaml`,
`observability/tempo/tempo.yaml`, `observability/grafana/provisioning/datasources/tempo.yaml`.

토픽 auto-create OFF. `depends_on: condition: service_healthy`.

### 3. contracts/order.placed.json

`order.placed` payload의 JSON Schema (draft 2020-12):
`{ order_id (uuid), items: [{sku, qty≥1, unit_price≥0}] (minItems 1), card_number (^[0-9]{13,19}$), amount≥1 }`.
전부 정수는 원 단위. `additionalProperties: false`.
정본. 덩어리 14 이후 CI에서 서비스 Pydantic 모델 출력 검증에 사용.
Slice 0 order-service는 `amount = Σ(qty × unit_price)`만 계산, 가격 검증은 Slice 1 (design doc §4.4).

### 4. pipeline-kafka: envelope 모델 + 직렬화

`Envelope` Pydantic 모델: `event_id`, `event_type`, `occurred_at`, `correlation_id`, `producer`, `schema_version`, `payload`.
헬퍼: `Envelope.new(event_type, correlation_id, producer, payload)` (event_id=uuid4, occurred_at=now).
`to_kafka(envelope) -> (key: str, value: bytes, headers: list[tuple])` — key=correlation_id,
headers에 `message-id`(=event_id), `correlation-id`. `traceparent`는 덩어리 6에서 주입.
`from_kafka(msg) -> Envelope` (Slice 1 컨슈머용이지만 지금 같이 정의).

### 5. pipeline-kafka: OTel 배선

`setup_telemetry(service_name)` — TracerProvider + OTLP/HTTP exporter(→ collector `:4318`) + resource(service.name).
`inject_traceparent(headers: list[tuple]) -> list[tuple]` / `extract_context(headers) -> Context` —
W3C TraceContext propagator를 Kafka 헤더에 매핑.
프로듀서(덩어리 6)가 produce 시 inject. 컨슈머(Slice 1)가 poll 시 extract.

### 6. pipeline-kafka: producer 래퍼

confluent `Producer` 얇은 래퍼. `KafkaPublisher(config)` + `publish(topic, envelope)`:
`to_kafka` → produce 스팬 시작 → `inject_traceparent(headers)` → `producer.produce(...)`.
flush 정책: 폴러가 배치 끝에 `flush()`.

### 7. pipeline-kafka: outbox

테이블 모델(SQLAlchemy declarative): `outbox(id BIGSERIAL PK, topic, key, headers JSONB, payload JSONB, created_at, published_at NULL, next_attempt_at)`.
- `enqueue(session, topic, envelope)` — 호출자 tx 안에서 행 INSERT.
- `OutboxPoller(session_factory, publisher, batch=100, interval=0.5s)` — asyncio 태스크.
  `SELECT ... WHERE published_at IS NULL AND next_attempt_at <= now() ORDER BY id LIMIT :batch FOR UPDATE SKIP LOCKED`
  → `publisher.publish` → `published_at = now()`. 단일 폴러/서비스, id 순.
  S0: 발행 실패 시 다음 tick. (백오프는 S2)

### 8. order-service: domain/

`OrderStatus` enum — 전체 정의 (PLACED, RESERVED, PAID, COMPLETED, CANCELLING, CANCELLED). S0은 PLACED만 사용.
`OrderItem` VO (sku, qty). `Order` 엔티티 (id, items, card_number, amount, status).
`Order.place(items, card_number) -> Order` 팩토리 (id=uuid4, status=PLACED, amount 계산).
프레임워크 import 0.

### 9. order-service: application/

포트 (Protocol): `OrderRepository.add(order)`, `OrderRepository.get(id)`.
`UnitOfWork` — `orders: OrderRepository`, `enqueue(topic, envelope)`, `__aenter__/__aexit__` (begin/commit/rollback).
유스케이스 `PlaceOrder(uow_factory)`:
```
async def execute(cmd: PlaceOrderCommand) -> OrderId:
    order = Order.place(cmd.items, cmd.card_number)
    async with uow_factory() as uow:
        await uow.orders.add(order)
        uow.enqueue("order.events", Envelope.new("order.placed", order.id, "order-service", payload))
    return order.id
```

### 10. order-service: adapters/outbound/

SQLAlchemy `orders` 테이블 + `SqlOrderRepository` (포트 구현).
`SqlAlchemyUnitOfWork` — async session 래핑, `orders` 프로퍼티, `enqueue`는 `pipeline_kafka.outbox.enqueue(self.session, ...)` 위임.
`__aenter__` = session 열기, `__aexit__` = commit/rollback + close.

### 11. order-service: adapters/inbound/

FastAPI:
- `POST /orders` — body(items, card_number) → `PlaceOrderCommand` → `PlaceOrder.execute` → `{order_id, status: "PLACED"}`
- `GET /orders/{id}` — `OrderRepository.get`, 없으면 404. Order를 응답 DTO로
- `GET /orders` — 목록
- `GET /health`

### 12. order-service: composition.py + main.py

`composition.py` — 설정(pydantic-settings) 읽기, async engine + session_factory, uow_factory,
`PlaceOrder` 조립, `KafkaPublisher`, `OutboxPoller`.
`main.py` — `setup_telemetry("order-service")`, FastAPI 앱, lifespan에서 `OutboxPoller` 태스크 시작/종료,
FastAPI instrumentation.

### 13. order-service: alembic

`alembic/` + `alembic.ini`. 마이그레이션 1개: `orders` 테이블 + `outbox` 테이블 (outbox 모델은 pipeline-kafka).
env.py는 async engine 사용.
